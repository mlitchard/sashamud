  It was a session registry. A GameSessionRegistry (TVar of Map Text 
  GameSession) that tracked active WebSocket sessions. Each GameSession held:

  lookupGameSession.

● Three approaches exist in the Servant ecosystem:

  1. Custom combinator — Write a Validated combinator that wraps ReqBody,
  decodes the JSON then runs validation before the handler sees it. Type-safe,
  composable, lives in the API type. William Yao's blog post is the best guide.
  2. WAI middleware — Intercept requests at the WAI layer before Servant touches
   them. Works but you lose type safety and have to manually decode/re-encode.
  3. Smart constructor in FromJSON — Make PlayerName's FromJSON instance reject
  invalid input during deserialization. Simplest, no new infrastructure, but
  error messages are generic JSON parse errors.

  Repos worth downloading for reference:

  - haskell-servant/servant — servant-server/src/Servant/Server/Internal.hs
  shows how ReqBody and AuthProtect combinators are implemented. That's the
  pattern for writing a custom Validated combinator.
  - haskell-servant/servant-auth — Real-world custom combinator that hooks into
  HasServer. Similar to what a validation combinator would do.

  Which approach do you want to go with? The custom combinator is the most
  Servant-native — validation becomes part of the API type, like Validated 
  PlayerName :> Post '[JSON] LoginResponse.
